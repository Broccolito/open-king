Verification

Benchmarks

Wall-clock time and peak memory for the same analyses run by both programs on the same inputs, on one machine. The method section states what was measured and what was excluded, so the numbers can be checked.

Draft

Every number on this page is a placeholder. The charts and tables show the intended presentation, not measured results. Replace the values and the machine description before publishing.

Method

Each case ran five times. The reported figure is the median of the last three runs, which drops the two runs that warm the page cache. Both programs read the same fileset from local disk and wrote to the same directory. Output files were compared after every run, so a timing is only reported for a run that produced correct output.

Ratio is reference time divided by open-king time. Higher means open-king finished sooner.

Thread scaling

The pairwise scan is the part that scales. Past eight threads the run is bounded by reading genotypes rather than by comparing them, so the curve flattens.

Peak memory

Genotypes are held in packed form and the pairwise scan allocates per thread, so memory tracks sample count rather than the number of pairs.

Reproducing these numbers

The corpus generator writes the same filesets on any machine from a fixed seed, so a timing run elsewhere compares against the same inputs. 

python3 tests/parity/generate_corpus.py --outdir /tmp/kingbench
scripts/bench.sh --impl target/release/king --reference /usr/local/bin/king
