Guide

Output files

open-king writes 23 distinct output files. All are terminated with a newline. Which of them a run produces depends on the analysis flag, the pedigree, the map and the sample count. Several can be absent, zero bytes or header-only after a run that succeeded, so the presence of a file is not evidence that the analysis found anything.

Before you script around these files

A successful run can write a 0-byte file. Testing for file existence, or for a non-empty file, is therefore not a success check. The single-family .kin case below is the clearest example: 6 samples in one family produce a .kin of exactly 0 bytes and the process still exits 0. Read the console lines and the exit status instead, and see Empty, header-only, absent for the full set of conditions.

How files are named

--prefix defaults to king. It is glued directly onto the suffix with no separator inserted, so the prefix and the suffix run together in the file name. A prefix containing / writes into that directory, which must already exist. 

king -b sexchr.bed --autoQC  --prefix ZZ_
king -b sexchr.bed --kinship --prefix ZZ_
king -b sexchr.bed --ibdseg --degree 2 --prefix ZZ_
king -b sexchr.bed --kinship --prefix run.2026
ZZ_.kin
ZZ_.kin0
ZZ_.seg
ZZ_X.kin
ZZ_X.kin0
ZZ_X.seg
ZZ__autoQC_Summary.txt
ZZ__autoQC_sampletoberemoved.txt
ZZ__autoQC_snptoberemoved.txt
ZZ__autoQC_updatesex.txt
ZZ_allsegs.txt
ZZ_splitped.txt
run.2026.kin
run.2026.kin0
run.2026X.kin
run.2026X.kin0

Three shapes are worth noticing in that listing. The allsegs.txt and splitped.txt suffixes carry no leading dot, so --prefix study gives studyallsegs.txt. The X suffixes carry no leading dot either, which is why run.2026 produces run.2026X.kin. And the --autoQC suffixes start with _, so a prefix ending in _ produces a double underscore.

--prefix is echoed in the Options in effect block only when it differs from king. A prefix naming a directory that does not exist is fatal: --prefix nodir/x exits 1 with Cannot open nodir/x$TMP$.ped to write.

That message names a 24th file. <prefix>$TMP$.ped is created and removed during the loader's writability probe, which runs after the .fam is opened and before a single pedigree row is parsed. It is not left behind on a successful run.

The InfType vocabulary

InfType is the inferred relationship label. It takes seven values, and they appear in .seg, .kin, .kin0 and cluster.kin. 

Dup/MZ   PO   FS   2nd   3rd   4th   UN

Dup/MZ is a duplicate sample or a monozygotic twin pair; PO is parent and offspring; FS is full siblings; 2nd, 3rd and 4th are those degrees; UN is unrelated. PO and FS are separated by IBD2 sharing when segment analysis is available (a true PO pair is IBD1Seg 1.0000 with IBD2Seg 0.0000), and by an IBS0 cutoff otherwise.

Cross-referencing files

.kin's InfType is not .seg's. .kin's Dup/MZ clause additionally requires HetConc > 0.8, so the same pair can print Dup/MZ in .seg and FS in .kin.

Row order

Three rules cover the pairwise files, and none of them is .fam order. Two of the three coincide with the obvious guess on small inputs and diverge on larger ones.

Files Order
.kin, .ibs, X.kin Families by a natural-sort comparator on FID, members by the same comparator on IID, then the i < j upper triangle. Digit runs compare by length first then bytes, so 7 < 70 < 007; non-digits fold to uppercase; a non-digit sorts before a digit.
.kin0, .ibs0 Pairs i < j over .fam row index, sorted by (i/B, j/B, i, j) with integer division. B = 32 for .kin0, B = 8 for .ibs0.
.seg, X.seg 16-sample blocks.

The block sizes were fixed by regenerating each candidate order against a 200-sample run and comparing to the emitted rows. 

.ibs0   19327 rows   block size that reproduces the order: 8   (rejected: 1, 16, 32, 64)
.kin0   19327 rows   block size that reproduces the order: 32  (rejected: 1, 8, 16, 64)
.seg      442 rows   block size that reproduces the order: 16  (rejected: 1, 8, 32, 64)

The remaining files: .con is serial i < j .fam order; bySample.txt is .fam order; bySNP.txt is .bim order within each chromosome class (autosomes and XY, then X, then Y, then MT); allsegs.txt is map order; cluster.kin is by cluster then the sorted-member upper triangle; updateids.txt is by original (FID, IID) while updateparents.txt is in cluster order.

<p>.kin0

Between-family pairwise relatedness: pairs whose two members are in different families. 8 columns under --kinship, 14 under --related. Under --kinship the file needs at least two distinct FIDs. Under --related it needs the between-family stage to detect something, and at degree 1 or 2 that stage also requires 100 or more samples.

<p>.seg

Per-pair IBD segment summary from --ibdseg. 8 columns, holding both within-family and between-family pairs in one file. 

FID1	ID1	FID2	ID2	IBD1Seg	IBD2Seg	PropIBD	InfType
# Column Meaning Format
1 to 4FID1 ID1 FID2 ID2The pair. FID1 == FID2 for a within-family pair.text
5IBD1SegProportion of the usable genome covered by IBD1 segments.%.4f
6IBD2SegProportion covered by IBD2 segments.%.4f
7PropIBDIBD2Seg + IBD1Seg/2, recombined from the two printed columns above.%.4f
8InfTypeInferred relationship.text

Rows are filtered. A pair appears only if it has at least one segment longer than 10 Mb, and only segments above the --seglength floor are counted.

PropIBD can disagree between files

.seg's PropIBD is computed from its own printed four-decimal columns, while every other file computes it at full precision. The two can therefore differ in the last digit for the same pair. That is faithful to the reference.

<p>build.log

A free-text record of what --build reconstructed. It has no columns and no header, and holds two line kinds.

X-chromosome files

Three files carry X results, and they are not variants of one layout. The same file name means different columns under different flags.

<p>X.kin

Under --kinship: within-family X kinship, 9 columns. The --kinship X pass runs when the map has 512 or more X markers, more than one family exists, and no --degree was given. 

FID	ID1	ID2	Sex	N_SNP	PhiX	Het	IBS0	KinshipX
# Column Meaning Format
1 to 3FID ID1 ID2The within-family pair.text
4SexA two-letter code in the row's own order. FM is a female ID1 and a male ID2.text
5N_SNPX markers called in both.%d
6PhiXPedigree X-kinship.%.4f
7HetThe pair's X heterozygosity denominator.%.3f
8IBS0Proportion opposite-homozygous.%.4f
9KinshipXEstimated X kinship.%.4f

Three estimators, chosen by the pair's sexes:

FF   Het = (Het_i + Het_j) / 2N     KinshipX = (HetHet - 2*IBS0) / (Het_i + Het_j)
FM   Het = Het_female / N           KinshipX = 0.5  - IBS0 / Het_female
MM   Het = H (imputed)              KinshipX = 0.75 - IBS0 / (N * H)

Samples whose .fam sex is neither 1 nor 2 are excluded from this pass.

Under --related: within-family X segment sharing, 9 different columns. The --related X pass has no 512-marker threshold and is not suppressed by --degree. 

FID	ID1	ID2	Sex1	Sex2	PhiX	IBD1Seg	IBD2Seg	PropIBD
# Column Meaning Format
1 to 3FID ID1 ID2The within-family pair.text
4Sex1.fam sex code of ID1, numeric rather than the two-letter code.%d
5Sex2.fam sex code of ID2.%d
6PhiXPedigree X-kinship.%.4f
7IBD1SegProportion of the usable X shared IBD1.%.4f
8IBD2SegProportion shared IBD2.%.4f

The single-family .kin is truncated

A dataset with exactly one distinct FID loses the tail of its .kin. Rows are flushed every 65536 bytes and the final partial buffer is never written. Under 64 KiB of content that leaves a zero-byte file. Measured: king -b nuclear.bed --kinship, 6 samples in one FID, leaves a zero-byte .kin and exits 0.

Above 64 KiB it leaves a file that ends, on a line boundary, at the last flushed chunk. Relabelling all 200 bigish samples into one family gives: 

one.kin:  1180057 bytes, 19546 rows of 19900

354 pairs are missing, and the byte count is 18 flushes' worth. With two or more distinct FIDs the file is complete regardless of size. This is a reference bug reproduced deliberately, because the alternative is disagreeing with KING.

Tiny datasets

N < 10 is the tiny-dataset gate. --unrelated, --cluster and --build print This function is currently disabled for tiny dataset with sample size < 10. at that size. --cluster and --build then write nothing at all, allsegs.txt included. --unrelated takes the same early exit and still writes both of its lists.

Two more small-sample substitutions change which files appear. --related below 10 samples becomes a --kinship run (--related is replaced with --kinship for a small sample size.), so the .kin is the 10-column form and the .kin0 the 8-column one. --ibdseg below 5 samples becomes a --kinship run in the same way (--kinship analysis carried out instead for such a small sample size.). Check the header before assuming which layout is on disk.
